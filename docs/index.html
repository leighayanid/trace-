Self-host with Neon

Your record, your database.

TRACE works fully offline. To sync across devices, point it at your own Neon Postgres.

  • LOCAL-FIRSTSQLite on the device is the source of truth.
  • NEON AUTHManaged Better Auth, one account.
  • DATA APINo backend to deploy.
  • RLSRows scoped to auth.uid().
  • CONFLICTSLast write wins. Deletes propagate.

  1. Clone and run, local-only

    No config needed.

    $ git clone https://github.com/leighayanid/trace-.git
$ cd trace-
$ flutter pub get
$ flutter run

  2. Create a Neon project and enable the Data API

    Neon Console → Data API → enable with Managed Better Auth.

  3. Apply the schema

    Run it in the Neon SQL Editor.

    -- paste into Neon → SQL Editor
db/migrations/001_schema.sql

  4. Point the app at your project

    Fill in the two URLs from the Neon Console.

    $ cp config/neon.example.json config/neon.json
    {
  "NEON_AUTH_BASE_URL": "https://ep-XXX.neonauth.REGION.aws.neon.tech/neondb/auth",
  "NEON_DATA_API_URL":  "https://ep-XXX.apirest.REGION.aws.neon.tech/neondb/rest/v1",
  "NEON_AUTH_ORIGIN":   "http://localhost:3000"
}

  5. Create your account and check it

    Answer y to create it, n to re-check later.

    $ bash tool/neon_check.sh

  6. Run with sync

    Syncs in the background once you sign in.

    $ flutter run --dart-define-from-file=config/neon.json

  7. Lock it down and ship

    Disables sign-ups, sets your trusted domain, builds the release.

    $ bash tool/ship.sh
